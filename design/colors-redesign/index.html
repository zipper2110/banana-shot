Colors tab — redesign proposals

This folder has one main proposal and two alternatives for the Colors tab. Each mockup is an HTML page with the app sidebar, the real texts and a frame of the reference video. The sliders work, and the frame shows an estimate of the color change. Use the switches at the top of each page to see adjusted values and a system without live color preview.

✓ Cosmetic changes only. No feature is added or removed.

To try a new accent color on option A, open the accent color test.

Problems in the current tab

  1. Too much empty space. Each slider row is 100 px high, with a gap of 60 px under the slider. Six values use about 650 px of the panel.
  2. No groups. The six sliders are one list with the same weight. The light controls and the color controls are mixed: Saturation is between Contrast and Shadows.
  3. The default is not visible. The default value 0 is the center of each slider, but the fill starts at the left end. The slider has no mark at 0. The user cannot see at one look which sliders are changed, or in which direction.
  4. Weak values. The value shows without a sign ("24", not "−24" or "+24"). A changed value and a default value have the same color.
  5. The meaning is only in the tooltips. The effect of Shadows and Highlights and the range of each slider are in tooltips only. The label "WB Temp" is an abbreviation.
  6. A hidden warning. When the system cannot show a live color preview, the tab adds this information only to the slider tooltips. The user can think that the sliders do not work.
  7. The playback controls use two rows. The play button is alone on a centered row above the seek bar. The time labels are 10 px monospace text.
  8. Reset does not tell its scope. "Reset" is a default button. Its text does not tell that it resets all six values.

Design principles

Zero is the referenceEach slider fills from the center. A tick marks 0. A changed slider has a lime thumb and a lime value.
Groups by purposeLight: Brightness, Contrast, Shadows, Highlights. Color: Saturation, Temperature.
Direction in wordsSmall end labels such as "Cooler" and "Warmer" tell the effect before the user moves the slider.
State at one lookThe header shows "2 of 6 changed" or "All at default". Reset is quiet when there is nothing to reset.
Visible limitsWhen live preview is not available, the panel and the video show a yellow notice.

Options

A · Grouped panel

Recommended

The layout stays the same: the video on the left and a 400 px panel on the right. The panel has a header with the changed count and "Reset all", two group cards, and a short footer. The playback bar is one row under the video.

  • The rows are 70 px high, not 100 px. All six sliders fit without a scroll bar.
  • Each row shows the label, the signed value, the center-fill slider and two end labels.
  • A lime bar at the left edge marks each changed row.
  • The footer tells that the values are saved to the project and used for export (text from the Colors help).
  • The playback bar is the same as in the Points final design: the play button with SPACE, the current time, the seek bar and the video length.

Best for
A clear structure with the smallest change to the current layout.
Swing effort
Low. A custom FlatSliderUI paints the center fill and the 0 tick (as ExportSliderUI). The rows are JPanels in two cards.
Risk
Low. The component names colors-* can stay the same, so the UI tests do not change.

B · Narrow panel with gradient tracks

Alternative

The panel is 320 px wide, not 400 px, so the video gets more width. The rows are compact, and the groups are plain captions, not cards. Each slider track shows its effect as a gradient.

  • The video is about 7% wider than in option A (1200 px, not 1120 px, in a 1600 px window).
  • The gradients show the effect: dark to light, flat to strong, gray to vivid, blue to orange.
  • Each slider has an icon. The icon is lime when the value is changed.
  • The gradient tells the direction, so the rows have no end labels. The rows are 56 px high.
Open option B →
Best for
Smaller screens, and users who judge the colors on a large video.
Swing effort
Low to medium. The gradient tracks need a custom slider UI. The layout is the same as today with a smaller panel width.
Risk
Low. A gradient is a weaker sign of a changed value than a lime fill. The Transform tab keeps a 400 px panel, so the two video tabs have different panel widths.

C · Faders

Alternative

The layout stays the same. The six sliders are vertical faders side by side, as on a mixing desk. The user compares all six values at one look. A details box under the faders shows the tooltip text of the active fader.

  • Each fader has the signed value on top, a scale with a long 0 mark, and an icon with the label below.
  • The fill goes up or down from the 0 mark.
  • The details box shows the name, the value, the description, the range and a gradient with the end labels.
  • The keys are the same as for a JSlider: the arrow keys, Page Up, Page Down, Home and End.

Text changes

  • "WB Temp" becomes "Temperature". The tooltip already uses "Temperature".
  • "Color Grade" becomes "Color grade" (sentence case, as the other tab headers).
  • "Reset" becomes "Reset all". The tooltip "Reset Color Grade to defaults" stays.
  • New status text in the header: "All at default" or "2 of 6 changed".
  • New end labels: Darker / Brighter, Flatter / Stronger, Deeper / Lifted, Darker / Brighter, Gray / Vivid, Cooler / Warmer.
  • New notice when live preview is not supported: "Live preview may not be available on this system. The values are still saved for export." It is the same information as the current tooltip note.
  • New footer: "Saved to the project. Export uses these values." It is the same information as the Colors help.

Notes

  • The colors come from UiStyles: DARK_BG, CARD_BG, LIME, GREEN and ACCENT_TEXT.
  • The live preview in the mockups is an SVG filter on a still frame. It is an estimate only. It is not the mpv filter chain.
  • The mockups use the Material Symbols font from Google Fonts for the icons. Without internet access, the icons show as words.
  • Add #preset=adjusted&support=none to a page URL to open it in a given state.
