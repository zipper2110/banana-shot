Points tab — redesign proposals

This folder has one main proposal and two alternatives for the Points tab. Each mockup is an HTML page with the app sidebar, a frame of the sample video and the points from the reference screenshot. The mockups work: press Space, C, V, A, Delete and the arrow keys, click the list and the timeline, and open the dialogs. Use the switches at the top of each page to see a pending point and the comments.

✓ Cosmetic changes only. No feature is added or removed.

Final design

Selected

The final design uses option B as the base, with these changes from the review:

  • Add comment moves from the mark panel to the right end of the playback bar.
  • The seek buttons show their keys as key chips, the same as Point start and Point end. Each key has its own chip, so Shift+Left shows two chips.
  • The play button shows "SPACE" as small text under the icon, as in the first Points design (design/points.html).
  • The seek buttons are one step brighter than the secondary buttons: lighter fill and border, white labels and a lime direction icon.
  • A seek hotkey (Left, Right, Shift+Left, Shift+Right) briefly gives its button a lime border.
  • The current time on the playback bar uses regular weight and a smaller size.
  • The "Points & events" header and the counts come from option C.
  • Each point row in the table is 45 px high.

Problems in the current tab

  1. The "−5s" button is hidden. On the screenshot, the left button group covers "−5s [shift+←]". Only "]" is visible, so the bar shows "Add comment -]". The three zones of the bar have fixed widths and overlap on smaller windows.
  2. The bar has no order. Point Start, Point End, Add comment and the four seek buttons have the same style. The lime play button is the strongest control, but the main task of this tab is to mark points.
  3. The pending point is easy to miss. After Point Start, only a "Pending…" card at the bottom of the list shows the state. The buttons and the timeline do not change.
  4. The list uses much space. A point card is 44 px high with a 10 px gap, so the screen shows 13 of 128 points. The start and end times have no column captions.
  5. Repeated key text. Each favorite card shows "[A]" next to the star. The seek buttons use long labels such as "+5s [shift+→]".
  6. The counts are hard to read. "128 Marked", "43 Fav" and "0 Comments" are small pills with an abbreviation.
  7. The timeline labels cover the tracks. "VIDEO", "MARKS" and "COMMENTS" are painted on the start of each track. The selected point is not visible on the timeline.
  8. The current time is far from the timeline. "Current time:" is at the right end of the bar, in small text.

Design principles

Marking firstPoint start and Point end are one group. The next step of the flow has the lime outline: first Point start, then Point end.
One state, three placesA pending point shows in the mark buttons, in the list and on the timeline at the same time.
Key chips, not key textKeys show as small chips. The tooltips keep the full text. Long labels such as "[shift+→]" go away.
Dense listA point uses one row with column captions. The screen shows about twice as many points.
Labels outside the tracksThe timeline gets a label column with the track names and counts. The tracks start after it.

Options

A · Clean toolbar

Recommended

The structure of the tab stays the same: video, bar, timeline and the list on the right. The bar has three zones: Mark, Playback and Time. The list has one row for each point.

  • Point start and Point end are one joined button group with the key chips C and V. The next step has the lime outline.
  • The seek buttons are short ("« 5s", "‹ 1s"). The key chips show only when the bar is wide. The zones cannot overlap.
  • The current time is large, at the right end of the bar, with the video length below it.
  • Three count tiles replace the pills: Marked, Favorites, Comments.
  • Point rows are 34 px high with the columns #, Start – End and Length. The star, Edit and Delete show on hover. The star of a favorite stays visible.
  • The pending point is a lime dashed card below the list, in the same place as now.
  • The timeline has a label column. Favorites are yellow, the selected point has an outline, and the pending point is a hatched range.

B · Mark panel and table

Alternative

A "Mark a point" panel at the top of the side column holds Point start, Point end and Add comment. The bar under the video has only playback. The list is a table.

  • Point start and Point end are two numbered step tiles. Each tile shows its time. While a point is pending, the End tile shows the playhead time.
  • A hint line below the tiles tells the next key to press.
  • The table has the columns #, Start, End, Length and ★. Comments are one-line rows with a color bar.
  • The play bar shows the time on the left and the transport in the center.

C · Editor stack

Alternative

The left column is a stack: status strip, video, timeline and controls. The timeline is directly below the video. The list uses the full height of the window.

  • The status strip shows the state: "Press C at the start of a point", "Playhead in point #4" or "Pending point from … 4.5 s so far".
  • The status strip also shows the keys Space, A and Delete.
  • The timeline shows the current time in its corner cell.
  • The controls have Point start and Point end on the left, the transport in the center, and Add comment on the right.
  • The list has 10-minute groups with sticky headers and the point count. Each point is a two-line card.

Please confirm

These changes show more of the current data. They add no function, but you can remove them.
  • The list shows the length of each point. The app calculates it from the start and the end.
  • The MARKS track paints favorite points yellow and draws an outline around the selected point.
  • The MARKS track shows a pending point as a hatched range from its start to the playhead.
  • Option B: the End tile shows the playhead time while a point is pending.
  • Option C: the status strip shows the point under the playhead, the pending length and the key legend. The list shows the point count of each 10-minute group.

Text changes

  • "Point Start [C]" becomes "Point start" with a key chip "C". "Point End [V]" becomes "Point end" with a key chip "V".
  • "Pending…" becomes "Pending point". The current tooltip already uses this term.
  • "43 Fav" becomes "43 Favorites".
  • The "[A]" text next to the star goes away. The tooltip "Favorite [A]" stays.
  • "−5s [shift+←]" and the other seek labels become short labels. The tooltips give the keys: "Seek back 5 seconds [Shift+Left]".
  • "Current time:" goes away. Option A adds "of 01:36:01.0" below the time.
  • In the Edit point dialog, "OK" becomes "Save". "Delete" moves to the left side and gets the red style.
  • The dialogs use the dark style of the app. The texts of the fields and the errors stay the same.

Notes

  • The colors come from UiStyles and SwingTimelineComponent: DARK_BG, CARD_BG, LIME, YELLOW, the mark green and the playhead red.
  • frame.jpg is one frame of PXL_20260913_070045619.mp4 at 00:18:12. The 13 first points are from the screenshot. The other points are generated.
  • The mockups use the Material Symbols font from Google Fonts for the icons. Without internet access, the icons show as words.
  • Add #mark=pending&comments=none to a page URL to open it in a given state. Add dialog=edit, dialog=comment, dialog=add or dialog=hint to open a dialog.
  • The mpv video is a native window in Swing. For this reason, no option puts controls or text on top of the video.
