Projects tab — redesign proposals

This folder has one main proposal and two alternatives for the Projects tab. Each mockup is an HTML page with the app sidebar, the real texts and 23 sample projects on three pages. The mockups work: open, rename and delete projects, import a new match, and go to the next page. Use the "Mockup state" switch at the top of each page to see an open project, no open project, the first start and the loading figures.

✓ Cosmetic changes only. No feature is added or removed.

Final design

Selected

The final design uses option C as the base, with these changes from the review:

  • The New project block shows the full workflow from the Overview help page in short steps: Import a match video, Mark the points, Score each point, Review the statistics, Export the video. The optional step "Tune the image at any time" is last. Each step shows the tab where the user does it.
  • The save note at the bottom says: "The app saves all changes automatically across all tabs. No need to save anything manually."
  • The logo is the current app mark. The mockup uses design/app-icon/app-mark.svg. The app keeps AnimatedAppMark.
  • The Video column shows one label with the absolute path, folder first. A long path loses the start of the folder, so the file name stays visible. The tooltip shows the full path.
  • The current project card also shows the absolute path as one label, on as many lines as necessary.

Problems in the current tab

  1. Too many primary buttons. Each row has a lime "Open Project" button. A full page shows ten lime buttons, and they compete with "IMPORT NEW MATCH".
  2. The open project has no mark in the list. The open project shows in the "Current Project" card and again as a normal row in the list. Only the disabled delete button tells which row it is.
  3. Much empty space above the list. Two 30 px gaps and two large green section labels push the list down. The screen shows fewer rows than it can.
  4. The file name is at the end of a long path. The second line of a row is the full video path. On a narrow window, the file name is cut first.
  5. The figures are hard to scan. The figure columns are centered. "Scored" shows "96/128" without a sign that it is a progress value.
  6. A missing video is easy to miss. Only a small red icon with a tooltip shows it. The row has the same lime "Open Project" button as the other rows.
  7. The pager is far from the list. "Prev", "Page 1 / 3" and "Next" are at the bottom left, below the scroll area.
  8. Weak empty states and mixed names. "No open project" and "No projects yet" are single gray lines. The text says "open from Existing Projects", but the section name is "Recent Match Projects". The buttons mix "IMPORT NEW MATCH" and "Open Project".

Design principles

One primary actionOnly "Import new match" has the lime fill. "Open" is a secondary button with a lime arrow.
Show what is openThe open project has a lime mark in the current project area and in the list at the same time.
File name firstThe path shows the file name in green and the folder in gray, as on the Export tab. The tooltip keeps the full path.
Numbers right-alignedThe figures use tabular digits and align on the right. "Scored" gets a thin progress bar.
Problems visibleA missing video shows "Video not found" in red and a red row mark. The tooltip text stays the same.

Options

A · Focused list

Recommended

The structure stays the same: header, current project, recent projects. The gaps are smaller, the current project is a clear card, and the list is a real table with the pager at its bottom.

  • The header is one row: the logo and the title on the left, "Import new match" on the right.
  • The current project card has a lime rail, a "CURRENT PROJECT" caption, the name, the file and the folder, and a "Rename" button.
  • The table has the columns Project, Duration, Size, Scored and Favorites. The figures align on the right.
  • Each row has two lines: the name, and the file with its folder. The open project has a lime bar and an "OPEN" tag.
  • Rename and Delete are gray icon buttons. They get brighter on hover. "Open" is a secondary button.
  • The pager is in the table footer. It shows only when the list has more than one page.
  • The first start shows three short steps: import, check the name, mark the points.

B · Project tiles

Alternative

The recent projects are tiles in a grid. A page of ten projects is two rows of five tiles. The current project is a slim bar below the header.

  • Each tile shows the name, the file name and a 2 × 2 block of figures with captions.
  • Rename and Delete are icons at the top right of the tile. "Open project" is a full-width button at the bottom.
  • The tile of the open project has a lime border and an "OPEN" tag. A missing video gives the tile a red top edge.
  • The pager is at the right of the "Recent projects" heading.

C · Start panel and list

Alternative

A fixed panel on the left holds the logo, the current project and a "New project" block with "Import new match". The right side is a dense list with one line for each project.

  • The "New project" block shows the three steps of the flow above the button.
  • The current project card shows the full path on two lines, so no text is cut.
  • The list rows are 44 px high. A full page of ten projects fits without a scroll bar.
  • A status icon starts each row: the open project, a missing video, or a normal video.
  • The pager is at the right of the "Recent projects" heading, with arrow buttons.

Text changes

  • "IMPORT NEW MATCH" becomes "Import new match". The other main buttons use the same case: "Create project", "Start export".
  • "Open Project" becomes "Open" (A, C) or "Open project" (B).
  • "Recent Match Projects" becomes "Recent projects". "Current Project" becomes a small "CURRENT PROJECT" caption.
  • The empty current project text "Use "IMPORT NEW MATCH" or open from Existing Projects" becomes "Import a new match, or open a project from the list below."
  • The empty list text becomes "No projects yet" and "Click "Import new match" to create one." Option A adds three short steps. Option B adds one sentence. Option C adds an arrow text to the New project block.
  • A missing video adds the red text "Video not found". The tooltip "The video is not on the disk anymore." stays.
  • A gray hint next to the heading: "Double-click a row to open the project". The same text is in the help now.
  • The New project dialog gets a step line: "Select the video", "Check the name", "Mark the points".
  • The scored bar has the tooltip "96 of 128 points have a score".
Decision needed: the Delete confirmation The mockups show "Cancel" and a red "Delete project" button. The app now uses the shared SwingUserDialogService.confirm with Yes and No. To get the new buttons, the Projects tab needs its own confirmation dialog, or the shared service needs button labels. If you prefer no change here, the dialog stays with Yes and No.

Notes

  • The colors come from UiStyles: DARK_BG, CARD_BG, CARD_BORDER, LIME, GREEN and ACCENT_TEXT.
  • Options A, B and C use a green square with a racket as a stand-in logo. The final design uses the current app mark. The app keeps AnimatedAppMark in all cases.
  • The file picker in the mockups is a fake system dialog. It shows only the order of the steps.
  • After Open, the mockup stays on the Projects tab and shows a note. The app opens the Points tab.
  • The mockups use the Material Symbols font from Google Fonts for the icons. Without internet access, the icons show as words.
  • Add #scenario=none, #scenario=empty, #scenario=loading, #page=2 or #dialog=new|rename|delete|error to a page URL to open it in a given state.
