# 1.3.0

The items of `backlog.md` that are done in this release.

### Beach tennis

- Decided on 2026-10-26: beach tennis is the third sport. A new beach
  tennis project uses the ITF rules: best of 3 tiebreak sets, a 10-point
  match tiebreak in place of the third set, and no-ad. In the statistics,
  a short point lasts 7 s or less, and a long point lasts 10 s or more.
  See `beach-tennis.md`.

### B-51 Drag a comment on the video

- Decided on 2026-10-24. In the Points tab, the user can drag a comment on
  the video with the mouse. The export puts the comment at the same place.
- No new window. The mouse input already goes to the video canvas. mpv
  draws the outline of the comment with the editor overlay
  (`setEditorOverlay`), the same as the crop editor.
- The project keeps the place as `position` of the comment in `edl.json`:
  `x` is the horizontal center and `y` is the lower edge, as fractions of
  the frame (0 to 1). A comment without `position` is at the default
  place: centered, in the lower third. Old projects do not change.
- `CommentAss` calculates the place for the preview and for the export.
  When the box of the comment does not fit at its position, the comment
  moves inside the frame. The text still wraps at 86% of the frame width.
- The drag:
  - The cursor changes over a comment, and an outline shows the comment.
  - During the drag, the comment stays on screen, also after the end of
    its duration.
  - Near the default center line and the default lower line, the comment
    snaps to the line, and a guide line shows. A comment at the default
    place gets no `position`. Thus, a drag back to the two lines resets
    the place.
  - The project gets the new position when the user releases the mouse
    button.
- A click on a comment without a drag selects the comment in the list. It
  does not play or pause the video.
- Decided on 2026-10-24: each comment has a size and an opacity.
  - The comment dialog has a Size slider (50% to 200%) and an Opacity
    slider (20% to 100%). The defaults are 100%. `edl.json` keeps them as
    `sizePercent` and `opacityPercent`.
  - The size multiplies all sizes of the comment: the text, the card or
    the pills, the outline and the shadows. The text still wraps at 86% of
    the frame width.
  - The opacity applies to the whole comment: the text, the backdrop, the
    outline, and the shadows. The minimum is 20%, so a comment does not
    become invisible.
  - The outline on the video has a handle at each corner. A drag of a
    corner changes the size. The center of the comment stays at its
    place. Near 100%, the size snaps to 100%.
  - Decided on 2026-10-24: a new comment starts with the last size and
    the last opacity that the user chose, the same as the style. The user
    preferences keep them for all projects. A new comment, a change in the
    Edit dialog, and a corner drag on the video set them. A move of a
    comment does not.
- Decided on 2026-10-25: each comment has a rotation.
  - `edl.json` keeps it as `rotationDeg`: whole degrees from -180 to 180.
    A positive angle turns the comment clockwise. The default is 0, so
    old projects do not change.
  - The comment turns around the center of its box. All parts turn
    together: the text, the card or the pills, and the outline. The
    shadows stay below the comment.
  - `position` keeps its meaning: the center and the lower edge of the
    comment before the rotation. When the rotated comment does not fit at
    its position, it moves inside the frame. The bounding box of the
    rotated comment must fit.
  - The outline on the video turns with the comment. It has a round
    rotation handle above the top edge, the same as the crop editor. A
    drag of the handle turns the comment around its center. Near 0°, 90°,
    -90°, and 180°, the angle snaps to that value. With Shift, the angle
    changes in steps of 15°.
  - The comment dialog has a Rotation slider (-180° to 180°). The default
    is 0°.
  - A new comment starts at 0°. The user preferences do not keep the
    rotation, because it is part of the place of the comment, the same as
    the position.

### B-50 Instant replay of a part of a point

- Show a part of a point again in the exported video: for example the ball
  near the line or a funny moment. The replay plays right after the end of
  its point.
- The user makes a replay on the Points tab. The UX mockup is
  `design/instant-replay/index.html`.
- The tasks, the open questions, and the seek prototype results are in
  `docs/replay/b-50-tasks.md`.
- Each replay has: a start and an end, a zoom frame on the video, and a
  speed from 0.1× to 1×. A replay plays once: decision 21 of
  `docs/replay/b-50-tasks.md` removed the repeat count.
- Decided on 2026-10-22:
  - A point can have more than one replay (for example the line call and a
    reaction).
  - A replay part can start up to 3 s before the point start and end up to
    3 s after the point end.
  - The zoom goes in smoothly at the start of the replay and out smoothly
    at the end. It is not a hard cut.
  - Sound: by default the sound slows down with the video. An option mutes
    the sound of the replay.
  - Each export includes the replays of each point that it includes. Full
    and Only points include all replays. Only favorites includes only the
    replays of the favorite points. The Export tab has no option to turn
    the replays off.
  - A replay is a piece of video that the app inserts after its point.
    The players on all tabs play it as a part of the source video, with
    its speed, zoom, and sound.
  - During a replay, the clock of the player shows only "Replay", not a
    time.
  - The seek keys and a click on the timeline move through a replay as
    through any other part of the video.
  - The marking keys (C, Q, W, E) do not work during a replay. "Add
    comment" during a replay is a separate item for later (B-52).
  - The zoom frame of a replay is on the video after the Transform tab
    (crop and rotation). The Colors tab settings also apply to the replay.
  - The live players do not use pre-rendered replay files. The app
    controls mpv: it seeks to the replay part, sets the speed, and sets
    the zoom as a smaller crop in the `tr-adjust.hook` shader. A prototype
    first measures the freeze at each seek.
  - The scoreboard is hidden during a replay.
  - Comments: the comments of a point also show over its replays, extended
    by the time of the replays. The user can also add comments over a
    replay.
  - The popup has a control for the effect at the cut into the replay and
    out of it, from a set of ready-made effects. The default is a fade.
  - The timeline of the Points tab shows each replay as a segment in the
    lime accent color after its point. The width of the segment is in
    proportion to the time that the replay adds to the video. The segment
    has no text. It has small spiky (zigzag) edges on all four sides
    (spike 4 px wide, 2 px deep), so it looks different from the video
    and the points. On the whole-match timeline a typical replay is about
    3 px wide: there it is a plain lime tick, at least 3 px wide. The
    spikes show only when the timeline is zoomed in.
  - The replay editor opens in a separate popup window with its own video
    player. The Points tab stays as it is in the main window.
- Decided on 2026-10-26:
  - The replays of one point play one after the other, in the order of
    their start times.
  - The popup is not modal. The user can use the main window while the
    popup is open.
  - No key adds a replay. The user clicks the replay button (on the
    playback bar, on a row, or "Add" in the popup).
  - A new replay starts 1.5 s before the playhead and ends 1.5 s after it.
  - The ruler of the Points tab timeline shows the times of the source
    video. It skips over the replay blocks, so a replay block has no time
    marks. Reason: the exported times are different for each export mode,
    and source times agree with the point list and the player clock.

### B-53 More thumbnail styles and a logo

- The design is the Claude Design canvas "Thumbnail Styles"
  (https://claude.ai/artifact/NNuzc1vU2ZbkTtHtBLVjwu). It has 25 styles
  in 5 groups: Street, Competition, Fight night, Bold blocks, and Sports TV.
  The pages "day" and "night" show the same styles on other frames.
- Decided on 2026-10-27:
  - The Share tab keeps the 6 styles of B-46 and adds the 25 new styles.
  - The app bundles the fonts of the design (Google Fonts, OFL license).
  - New text fields: Round (for example "SEMI-FINAL"), Club name (the
    text under the logo), and Score (for example "6-4 7-5"). The score is
    never a preset, because many users do not want to show the result.
  - The user can add a logo file: PNG, JPG, GIF, BMP, TIFF, WEBP, or SVG.
    The logo and the club name stay for the next project, as the style.
  - A row of group buttons (Classic and the 5 new groups) is above the
    style cards. The cards of one group show at a time.
  - The app keeps a PNG copy of the logo (logo.png, 1024 px or less) in
    the app data folder. FFmpeg reads WEBP. JSVG draws SVG.
  - A text with letters that a design font does not have (for example
    Cyrillic) uses the font of the B-46 styles.
  - Only the new styles show the logo. The 6 B-46 styles do not change.
  - The text under the logo is the "Brand name" field. Its field is
    directly under the logo controls.
  - The brand name has its own font (the font of the style, or one of the
    bundled fonts) and its own color (the text color of the style, or a
    color). The font and the color are the same for all styles and go to
    the next project, as the logo.
  - The brand name is the same in all projects. The app saves it as the
    user types, as the logo.
  - The thumbnail shows the brand name as the user types it. The app does
    not change it to capital letters. (Decided on 2026-10-27.)
  - The shadow around the brand name contrasts with its color: black
    around a light color, white around a dark color. (Decided on
    2026-10-27.)
  - Lightning: the first team is at the left edge, and the second team is
    at the right edge. (Decided on 2026-10-27.)
  - The Score field accepts any text. A text of set scores only (for
    example "6-4 7-5") shows as set scores. Another text shows as the user
    types it: Scoreline shows it in the large score font, and Score bug
    shows it in one cell at the right of the team rows. (Decided on
    2026-10-27.)
  - One text field goes to one label on the thumbnail, and one label shows
    one text field. No label shows another field when its field is empty.
    The fields have the same names in all styles, so the texts stay when
    the user selects another style.
  - In the artboards, some styles show the round in the place of the large
    words. These styles show the large words there, and have no Round
    field. Only Split XL, Score bug, and Alert have a Round field, because
    they have a separate place for it.
  - The Colors tab shows only the color roles that change the thumbnail of
    the style. A role that only colors the brand name is not there.
  - All colors of the thumbnail can change. New roles: Accent 2 and
    Accent 3 (the sides of the two teams, and the red parts of the TV
    styles), Light box (the paper, the info bars, the cards, and the score
    cells), and Text on light box. The gray texts and lines of a light box
    come from the light box and its text color.
  - The color sets give a value to all roles, so that a set changes all
    styles in the same way.
  - The Share tab does not show a note about long or small texts.

### B-11 Localization: the first app languages

- B-11 is not complete. It stays in `backlog.md`. This release has the
  first app languages: Spanish (Spain and Latin America), Russian,

  language (E2).

  translated texts come with the next release.

  the default side names. They show in the current language. A user who
  types exactly a default text (for example "Team 1") gets the default
  text of the current language.
- The status of each epic is in `docs/localization/`.

### B-54 "What's new" popup for a new version

- Show the main changes of a new version to the users of older versions.
- Decided on 2026-10-27:
  - Each release has one Markdown file with its images on the site, for
    example `site/public/changelog/<version>/whats-new.md`. The content has
    no fixed structure: rich text, lists, images, and links.
  - The extended page on the site is a separate page. The author writes it.
    No script makes it from the Markdown file.
  - `latest` in `release/version-policy.json` gets two optional fields:
    `whatsNewUrl` (the Markdown file) and `pageUrl` (the extended site
    page). Released builds ignore new fields.
  - When the app finds a newer version, it shows the "What's new" popup.
    The popup shows only one time for each new version.
  - The user can close the popup. The popup does not stop the user.
  - The popup has:
    - A header with an icon, "A new version is out", and a close button. The
      header shows no version text.
    - The Markdown page in a scroll area. Under the page, above the line of
      the buttons, a "Read more on the site" link opens `pageUrl` in the
      browser. The app adds this link. The Markdown file does not need it.
    - The buttons "Later", "Manually download update", and "Update and
      restart".
  - The update notice bar stays as it is now. It gets a link to the site
    page (`pageUrl`).
  - The app converts the Markdown to HTML with commonmark-java (BSD-2) and
    shows it in a `JEditorPane` with an app style sheet. Images fit the
    width. Links open in the browser.
  - If the Markdown file does not load, the popup shows the `notes` and the
    site link.
  - Builds 1.0 to 1.2 show only the `notes` in the bar.
  - Not now: the page at the first start after the update.
- Done on 2026-10-27. With no `whatsNewUrl`, no popup shows: only the
  notice. The rules are in `build-expiry-spec.md` ("What's new popup") and
  S-02 of `docs/licensing/expiry-scenarios.md`. The release steps are in
  `release-checklist.md` (section 9).
