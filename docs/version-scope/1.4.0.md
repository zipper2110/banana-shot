# 1.4.0

The items of `backlog.md` that are done in this release.

### B-63 Scoreboard start and end settings, and a preview that stays while marking

- Problem (user report, 2026-10-31): the Points tab preview hides the
  scoreboard 20 s after the last marked point. While the user marks the
  next point, the scoreboard goes away and then comes back. The preview and
  the "Full video" export now use the same timeline
  (`ScoreboardTimelineBuilder`, `fullVideo = true`), so the export rule
  also hides the board in the editor.
- Current behavior of the "Full video" export (2026-10-30): the scoreboard
  starts at the first scored point and fades in. After the last point it
  shows the final score for 20 s and fades out. The fade is 0.5 s.
- Decided on 2026-10-31:
  - Add two settings to the scoreboard settings dialog:
    - Start: First point (the default), Video start, or Fixed time.
    - End: Right after the last point (first named "Hide at once"), 5 s,
      10 s or 20 s after the last point (the default is 20 s), Until the
      video ends, or Fixed time.
    - Decided on 2026-11-01: "Right after the last point" does not show the
      final score. The board shows the score before the last point and
      fades out at the end of that point. Keep this behavior.
  - Fixed time: a time field (`hh:mm:ss`) and a "Use the current position"
    button. The button takes the preview position when the dialog opens.
    Do not use the word "playhead" in the texts.
  - A fixed time belongs to the video of this project. "Use as my default"
    does not keep it. If the default has "Fixed time", a new project uses
    First point or 20 s.
  - If the fixed start is after the fixed end, the dialog shows an error
    and does not save. A fixed time after the video end means "Until the
    video ends".
  - A fixed start after the first point, or a fixed end before the last
    point, is allowed. Then some points have no board. The dialog shows a
    short hint, not an error.
    - Decided on 2026-11-01: the hint tells which setting hides the board:
      the start is after the first point, the end is before the last
      point, or both.
  - The preview with the default end (a time after the last point):
    - The match has not ended by the score: the board stays until the
      video ends. This is also true for "Sets, no match end".
    - The match has ended by the score (`matchEnded`), also with points
      after the match end: the board ends as in the export.
  - The preview with "Until the video ends" or a fixed time: the board
    follows the setting exactly, also while the user marks points.
  - The export always follows the settings. An incomplete markup with the
    default end hides the board 20 s after the last point.
  - The fade stays 0.5 s and has no setting. There is no fade at the video
    start or the video end. The preview shows no fade.
  - The "Only points" and "Only favorites" exports ignore these settings.
  - With a trim (B-62), "Video start" and "Video end" mean the trim start
    and the trim end.
- Tests: the preview cases (match not ended, match ended, points after the
  match end), each start and end option in the export timeline, the fixed
  time validation, and the default that drops a fixed time.
- Done when: the user can set the start and the end in the scoreboard
  settings, the export follows them, and the preview keeps the board while
  the user marks points of a match that has not ended.

- Done on 2026-10-31:
  - `ScoreboardSettingsV1` has `start`, `startMs`, `end` and `endMs`. A
    file without them gets First point and 20 s after the last point.
  - `ScoreboardTimelineBuilder.fullVideoRange` gives the range of the
    board. The "Full video" export gives it the video length, so "Until
    the video ends" and a fixed time after the video end have no fade.
  - `ExportTrim.overlays` removes the fade where the trim cuts the board.
  - The default scoreboard settings (`forDefault`) have no fixed time.
  - The Scoreboard settings dialog has the group "When to show" (first
    named "Start and end", renamed on 2026-11-01). It shows
    a red error for a time that is not valid and for a fixed start after
    the fixed end. Then Save is not available. The time field and the
    "Use the current position" button show only for "Fixed time".
  - The Points tab buttons are now "Scoring rules" and "Scoreboard
    settings".
  - Tests: `ScoreboardTimingTest`, `ScoreboardTimeTextTest`.

### B-13 step 10: bundled scoreboard fonts and a font setting

- 1.4.0 is a Windows release. The macOS version (B-13) is not part of it
  (decision of the author, 2026-11-03), so the repository variable
  `MACOS_RELEASE` stays unset. These B-13 changes are already on `master`,
  so 1.4.0 has them: the bundled fonts and the Font setting (checked on
  Windows by the author on 2026-11-03), the neutral texts ("the system",
  "computer"), and the playback counts in the preview log.
- Done on 2026-11-03. Details are in `docs/macos/b-13-macos.md`, "Result of
  step 10".
- The scoreboards, the statistics card, and the comments use bundled open
  fonts in place of the Windows fonts. The Scoreboard settings dialog has a
  new "Font" list.
- Changelog note (for `site/public/changelog/index.html` at the release):
  "Scoreboard: the app now has its own fonts, so the scoreboards, the
  statistics card, and the comments look the same on each computer. A new
  export of an existing project looks a little different. You can also
  select one font for all text of the scoreboard in Scoreboard settings
  &rarr; Font."

### B-58 Analyze the 404 requests of the site

- Get the list of the requests to the landing site that got a 404 page. The
  404 page sends its path to the counter (`data-path` in
  `site/public/assets/count.js`), and the site Worker reports the HTML
  requests to the analytics Worker. Also look at the Cloudflare analytics of
  the zone.
- Put the paths in groups: old or wrong links to our pages, links from other
  sites, bots and scanners (for example `/wp-admin`), and other.
- For each group, find out if an action is useful. Examples: a redirect to
  the correct page, a fix of a wrong link, a new page, or no action.
- Done when: the groups and the decision for each group are in this item, and
  the useful actions are new tasks or new backlog items.
- Done on 2026-11-02. The data is from the bot counter (`site_bot_daily`)
  and the page view counter (`site_daily`, path `/404`), from 2026-10-13 to
  2026-11-02. Of 1,247 HTML requests of bots, 817 got a 404. People saw the
  404 page one time.
- Groups and decisions:
  - Wrong links to our pages: none. All links of the site pages,
    `sitemap.xml`, and the app go to pages that exist. One request for
    `/sports/` on 2026-10-27 came before the deploy of that page. No action.
  - Links from other sites: none. The one 404 view of a person was a direct
    open on 2026-10-13, probably a test of the author. No action.
  - Icons at fixed root paths (22 requests): `/favicon.ico`,
    `/apple-touch-icon.png`, `/apple-touch-icon-precomposed.png`, and
    `/favicon.png`. Browsers, link previews, and crawlers ask for them.
    Action: done. The first three files are now in `site/public/`.
    `/favicon.png` is not a standard path (3 requests of scripts). No
    action.
  - Scanners (757 requests): `/wp-admin/install.php` (704), web shell
    paths such as `/images/images/cache.php` and `/.svn/wc.db`, and secret
    files such as `/.env.local`, `/config.yml`, and `/secrets.json`. Some
    of them use the name Googlebot or GPTBot, but real crawlers follow
    links. The site is static, so they find nothing. No action.
  - Standard files that the site does not have: `/.well-known/security.txt`
    (15), `/.well-known/traffic-advice` (12, the prefetch proxy of Chrome:
    a 404 means "allowed"), `/llms.txt`, `/ai.txt`, `/humans.txt`,
    `/ads.txt`, and `/.well-known/ucp` (1 each). No action now.
    `security.txt` and `llms.txt` are optional for later.
  - Long or unusual paths (`404 (other)`, 5 requests). The counter does not
    keep them. No action.
- Limits: the 404 page of a person sends only `/404`, not the requested
  path. Thus a wrong link on another site shows only its referrer. The
  Cloudflare analytics of the zone were not checked: they need an API token
  with analytics access. Check again when the site gets more traffic.
